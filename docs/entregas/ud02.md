# UD2: conexión y estructura relacional

## 1. Alcance

Implementado:

- `FabricaConexiones.abrir()`: abre JDBC con la URL y las `Properties` validadas de
  `ConfiguracionBD` para SQLite y PostgreSQL, y activa las claves foráneas de
  SQLite en cada conexión. El cliente cierra la conexión (`try-with-resources`).
- `EsquemaJdbc.crear()`: prepara el namespace de PostgreSQL cuando corresponde y
  ejecuta el DDL de las cuatro tablas (`empresa`, `estudiante`, `tutor`,
  `asignacion`) con `IF NOT EXISTS`, por lo que repetir la preparación conserva
  las filas.
- `EsquemaJdbc.comprobar()`: valida por metadatos tablas, columnas, tipos,
  nulabilidad, PK y FK; en SQLite exige además que `PRAGMA foreign_keys` esté
  activo.
- `EsquemaJdbc.reiniciar()`: exige entorno `pruebas` y confirmación explícita;
  vacía solo las cuatro tablas del caso en orden de dependencias y conserva las
  tablas ajenas.

Fuera de alcance: no hay CRUD de negocio (UD3), ni pool en esta fábrica, ni
ofertas, plazas o documentos de seguimiento. El CSV/JSON de UD1 sigue funcionando.

## 2. Ejecución

Versiones comprobadas: Java 21 (Temurin 21.0.13.1), Maven 3.9.9, SQLite JDBC
3.53.4.0 y pgJDBC 42.7.10. En mi entorno local no había Docker, así que la
verificación de PostgreSQL se hizo con PostgreSQL 18.6 standalone; el contenedor
didáctico usa PostgreSQL 17 sin cambios de código. Python 3 para el guion.

Comandos (desde la raíz del repositorio):

```bash
mvn -B clean test
mvn -B -f ud01/practica/pom.xml -Pcontrato clean verify
mvn -B -Pcontrato-ud02 clean verify
mvn -B -Pcontrato-ud02,postgresql clean verify
```

SQLite (archivo dedicado a pruebas en `datos-demo/`, ignorado por Git):

```bash
mkdir -p datos-demo
export FCT_JDBC_URL='jdbc:sqlite:datos-demo/ud02.sqlite'
export FCT_ENTORNO='pruebas'
python3 herramientas/preparar_bd.py crear
python3 herramientas/preparar_bd.py comprobar
python3 herramientas/preparar_bd.py reiniciar --confirmar-pruebas
```

PostgreSQL (en Codespaces, host `db`; en mi verificación local, `localhost:55432`):

```bash
export FCT_JDBC_URL='jdbc:postgresql://db:5432/fct_pruebas'
export FCT_DB_USER='fct'
export FCT_DB_PASSWORD='fct_laboratorio'
export FCT_DB_SCHEMA='fct_ud02'
export FCT_ENTORNO='pruebas'
python3 herramientas/preparar_bd.py crear
python3 herramientas/preparar_bd.py comprobar
```

## 4. Decisiones

- **Cargar el DDL de `src/main/resources/sql/ud02/`** en vez de duplicarlo en Java:
  mantiene una única fuente por gestor y deja la diferencia de fechas
  (`TEXT` en SQLite, `DATE` en PostgreSQL) explícita en el recurso.
- **Comprobar con metadatos**, no con `SELECT 1`: `getTables`, `getColumns`,
  `getPrimaryKeys` e `getImportedKeys`. Así `CREATE TABLE IF NOT EXISTS` no oculta
  una tabla con columnas o tipos erróneos.
- **Agrupar las FK importadas por tabla referenciada** y comparar el mapa
  columna local → columna remota. Esto valida también la FK compuesta
  `(tutor_id, empresa_id) → tutor(id, empresa_id)` que exige que el tutor sea de
  la empresa de la asignación.
- **Activación de FK en SQLite**: las `Properties` ya lo piden, pero se ejecuta
  además `PRAGMA foreign_keys = ON` en cada apertura y `comprobar()` verifica el
  `PRAGMA`, porque SQLite no mantiene esa opción entre conexiones.
- **PostgreSQL**: `crear()` ejecuta `CREATE SCHEMA IF NOT EXISTS` y
  `SET search_path` con el namespace ya validado por `ConfiguracionBD`, sin tocar
  `public`.
- **Reinicio seguro**: exige `FCT_ENTORNO=pruebas` y `--confirmar-pruebas`;
  vacía solo las cuatro tablas en transacción y en orden de dependencias
  (`asignacion → tutor → estudiante → empresa`), sin `DROP DATABASE` ni cascadas.
  Las tablas ajenas permanecen.
- **Cierre de recursos**: `FabricaConexiones` cierra la conexión si falla la
  apertura; `DemoConexion` y las pruebas usan `try-with-resources`.

Límite conocido: la comprobación de fechas de SQLite es lexicográfica (`TEXT` ISO);
detecta orden entre fechas válidas, pero no valida todo el calendario. La
validación de dominio de Java sigue siendo necesaria para eso.

## 6. Demostración

Pasos sobre `trabajo/`, reproducibles desde la raíz:

1. **SQLite crear/comprobar/cerrar**: con `FCT_JDBC_URL=jdbc:sqlite:datos-demo/ud02.sqlite`
   ejecutar `crear`, abrir otra ejecución (`comprobar`) y ver `Conexión cerrada`.
2. **PostgreSQL crear/comprobar**: arrancar `db`, exportar URL/usuario/clave/esquema
   y repetir `crear` y `comprobar`; la salida indica `gestor=PostgreSQL`.
3. **Credencial inválida y corrección**: ejecutar `comprobar` con
   `FCT_DB_PASSWORD` errónea (falla `SQLState=28P01`, código 1); corregirla y
   repetir con éxito.
4. **Restricciones y tabla ausente**: `CasosEsquema` demuestra rechazos de FK,
   fechas y borrado referenciado; borrando `asignacion`, `comprobar` falla.
5. **Reinicio seguro**: con una tabla `ajena` creada en el namespace, ejecutar
   `reiniciar --confirmar-pruebas`; `ajena` conserva sus filas.
6. **Aceptación en ambos gestores**: `-Pcontrato-ud02` (SQLite) y
   `-Pcontrato-ud02,postgresql` (ambos), explicando el límite de fechas de SQLite
   y que PostgreSQL exige servicio y credenciales externas.
